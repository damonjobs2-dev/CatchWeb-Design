# 可视化设计规范页面

## 交付

主入口为本次任务目录的 `index.html`，归档方式见 [任务文件归档](report-contract.md#任务文件归档)，在 file:// 下离线可用；截图与附件使用相对路径，一起交付目录。不占用产品测试端口；需要预览服务时用临时独立端口。统一 CatchWeb-Design 文档框架负责导航和状态控制；样例区域独立应用原站样式。壳层的字体、按钮、间距不算原站 Token。

页面以可视化表达设计基础和实际采集的组件：色卡带值和用途；字体用真实文字样张与参数；间距布局用图示；组件使用状态并排对照与交互预览；页面地图有缩略图、模块关系和响应式说明。长说明可折叠，关键结果直接可见。读者页面不展示采集范围、方式、时间、工具、证据面板和原始数据下载入口；工程附件内部继续保存证据。影响设计结论的估计或未验证参数仍就地说明。概览直接概括原站设计，不额外制作会被误认为官网 Logo、原图或实际页面的装饰封面。

## 定版框架与品牌适配

制作展示页时读取 [文档风格规范](document-style.md)。该文件是版式、字级、留白、样例尺寸和主题的单一规范；以配套共享 CSS 和模板实现。默认保持已定版的 B 风格，每次依据原站品牌色调整文档强调色及淡色辅助层。品牌色的来源记录在证据中，原站样例参数保持原值。

连续阅读目录以实际滚动位置更新；到达底部选中最后一个实际章节，不用旧 hash 锁定高亮；向上阅读、锚点恢复与窗口变化后重新判断。使用 assets/study-navigation.js 可复用已验证逻辑。

## 基础内容的展示方式

读者页面用留白区分章节、字体样张和参数，不使用装饰性分割线；原站边框样例保留。

基础页面采用 getdesign 示例的展示语言：简短说明、真实视觉样例、精简参数与用途说明。仅保留设计结论、应用位置和必要参数；重复图示内容、数值含义或处理方法的解释小字省略，影响准确性的限制用短语就地标注。框架和品牌主题按文档风格规范执行，样例内部保留被分析网站的视觉。

- **色彩**：先整体简述，再分品牌色、主色和辅助色。每张卡片展示大色块、名称、色值（含透明度）、对应位置和应用描述。相同颜色可在不同用途出现。无法确认官方品牌身份时标明按观察用途归类；区分声明变量和实际应用，避免将未使用变量全部展示成已用色。
- **字体**：按实际字号从大到小排列。每行展示位置或标准用途名称、字号、字重、行高、字距与字体信息，并使用原网站实际文本作为样张。样张应用可取得的原站字体；替代字体或未确认的回退须说明。图片中的文字不认作 CSS 字号。
- **间距**：用尺寸递增的条形和数值展示已采集间距，每项描述具体用途。内外边距与元素 gap 可分开呈现。未经验证的值不补成完整阶梯，也不自动命名为 xs/sm 等 Token。
- **圆角**：用紧凑表格列出应用位置、原始数值、局部转角预览，参照 Refero 的局部圆角呈现方式。预览裁出左上角以突出弧线，不再给每个值单独放一块大演示区。胶囊等大值保留原始数值，浏览器对预览容器的归一化不改写数据。不存在的档位不补齐。
- **布局、边框和阴影**：保持相同的留白、标题层级与样例优先的表达；提供布局关系示意、边框样例和阴影表面。图标须有特色或有意义的多种样式才展示；示意与原站实测值分开说明。

当用户只要求部分一级类时，仅展示该范围的导航和内容；其余范围留在证据的覆盖说明中，不补空白章节。数据缺口保存在内部证据，影响当前设计解读的未验证参数就地说明。

### 面向读者的参数表达

基础内容默认连续滚动浏览，目录作为章节锚点并跟随阅读位置高亮。保留所有章节在文档流中，避免为阅读下一项必须点目录。

样例的应用位置用自然语言描述；CSS 类名、选择器和原始声明保留在证据或折叠的工程详情中。颜色统一显示大写六位十六进制色号，透明颜色另标不透明度百分比，保留原始透明度用于绘制和证据，不把透明色直接转换为不透明色。

字体声明按“英文字体：名称（英文名）”“中文字体：名称（英文名）”简要列出；本身就是英文名时直接使用。用简短注释区分声明的候选字体与实际渲染字体，避免长篇解释字体选择顺序。字体参数标明“字号”“字重（常规/中等/半粗等）”“行高”，避免只列斜线分隔的数字。内边距用容器与内容的可视化样本标出上、下、左、右尺寸，说明它是边缘到内容的留空，与元素之间的间隔区分。示意放大时注明放大，标注仍用原始像素值，0px 如实显示。基础条目默认用规范示意图和数值展示，不要求为每个内边距或圆角另行采集、记录和嵌入官网截图。用户临时要看官网实例时，按其指定的交付位置提供；只在会话查看的实例不加入规范页面，也不升级为后续固定采集要求。布局图标出整体显示区、版心、内容区和左右留白；依据同一视口的几何计算占比，同时说明 max-width 是否包含内边距。占比在读者页面四舍五入为整数，绘制和证据保留精度；章节宽度有差异时分别标注，不把单个区域的比例推广为全站固定比例。

边框和阴影内容较少时，使用小样例与参数侧排，演示底只包住样例，避免铺满整行；不重复说明应用位置。窄屏上下排列。内边距采用小尺寸容器图与独立 HTML 标注，标注约 12px，避免 SVG 缩放导致字体变大；桌面可将四种样本放在一行，窄屏两列。参数按“标签在上、值在下”排列，单层省略层级标题与重复图注。阴影默认展示一个有代表性的视觉样例和易读参数：颜色（大写十六进制）、不透明度、水平偏移、垂直偏移、模糊范围和扩散范围；说明内阴影时的类型。多层阴影逐层列出。实际无法测量的字段写「未测量」，不猜测或把未知当成 0；可根据明确省略而生效的 CSS 初始值标注 0。原始 CSS 保存在工程证据中。

## 页面类的分类与展示

页面所有元素统一按设计价值筛选，导航、按钮、卡片、标签、输入、表单、弹窗、定价及其他类别均不因名称或存在而自动展示。满足以下任一条件且有原站证据时可展示：具有鲜明辨识度或可复用的设计特色；不同状态存在容易辨别的视觉变化；同类存在多种有意义的样式或组合，值得比较。说明每个入选元素带来的具体参考价值。

普通的单一样式、区别细微的悬停状态和重复示例可以省略；仅挑选足以说明设计规律的少量代表。特色本身突出的单个元素仍可展示，不强求必须存在对比。用户明确指定分析某类元素时按要求展示，并如实说明其特色和证据。证据不足时不把猜测当作特色。二级菜单随筛选结果动态生成，未入选的分类不显示空菜单。 所有类别都未入选且没有其他页面内容时，不显示空的「页面」一级菜单；按钮、卡片等也没有最低展示数量。

Agent 可以补充具有设计价值的网站特色分类，例如瀑布流、图片查看器、商品规格或生成工作台，说明单列理由；能归入已有分类的变体留在原分类，避免重复建菜单。

所有分类共用 CatchWeb-Design 文档框架、标题层级、字体、内容宽度、对齐轴线、留白与自适应规则，保持与概览和基础一致；只在样例内部应用被分析网站的样式。不为新增分类另设计皮肤，不增加装饰性分割线，不把原始选择器、CSS 和采集工具信息放进读者正文。

每个分类先用简短自然语言概括设计和用途，再展示少量有代表性的视觉样例、应用位置、必要尺寸和内部布局。只有状态差异对理解设计有帮助时，才用并排样例或本地预览展示；未观察到或只读到 CSS 声明的状态须分别标明，不为了凑齐状态补造默认、悬停、焦点、按下、选中、禁用、加载、错误或成功样式。参数使用中文标签，颜色沿用十六进制表达，详细证据留在工程附件。

交互预览局限于本地：切换、展开、关闭、输入示意可操作，表单不发送数据，按钮不调用原站接口；文档的控制按钮和辅助焦点标识不认作原站设计规范。复杂或跨域组件只复现已确认部分，说明哪些仅有外观而没有行为；不声称完整还原未验证流程。默认连续滚动，二级菜单定位到分类。

### 样例的分组、对齐与组合展示

以下仅适用于通过设计价值筛选或用户明确要求展示的元素。参考 GetDesign 的展示结构，不把参考站的样式、业务内容或推测状态当成原站证据。

- 简单控件集中比较：按钮按类型与已确认状态共用一个紧凑展示面，避免给每个小按钮包一张大空卡。标签和输入框也采用清晰的分组、贴近样例的名称与说明。
- 输入与选择：字段名放在控件上方；同组控件对齐左边缘、顶部与文本基线，说明置于对应控件下方。演示填充值使用明确的示例文本，不视为新增状态，不使用个人信息。
- 卡片：先区分通用容器和产品、功能、评价等用途变体，再按实际内容组合图片、标题、说明和行动入口；用途变体留在卡片类别内。状态并排时统一尺寸与内容，避免内容差异掩盖样式差异。
- 表单：展示可理解的完整组合，包括标题说明、字段分组、必要声明和操作区，不仅堆放单个输入框。保留原站单列或双列结构；文档结构说明可与样例并排，窄屏堆叠。未确认选项不伪装成原站禁用状态。
- 定价等复合模块：同组的名称、价格、单位、适用对象、权益和行动入口按相同顺序对齐。文案长短不同也应保持比较轴线；不擅自添加原站没有的推荐标记或强调档位。
- 弹窗：在文档内的遮罩画布中直接展示外壳、内容区和操作区；必要时另提供本地打开、关闭、Esc 与焦点返回体验。文档示意遮罩和未取得的内容要明确标注，不冒充原站参数。底部操作区只在原站确有该结构时复现。
- Toast、空状态、错误、加载等仅在原站实际出现或有明确样式证据时展示。存在多个语义变体时可用统一宽度纵向排列，对齐图标、标题、正文和关闭入口；不为套用参考预览补造信息、成功、警告、错误四种状态。

简洁控件使用 compact 展示面；完整卡片或表单使用 panel；浮层使用 overlay。以上为文档呈现模式，背景与布局辅助属于 CatchWeb-Design，不改变样例内部的原站样式。工程附件记录呈现参考与原站证据的不同来源。保持既有基础模块不变。

## 组件状态

针对筛选后需要研究的组件采集 default、hover、focus、active、selected、disabled、loading、error、success 的适用状态；不适用与未采集分别说明。每个状态记录原站截图/样式读数、证据编号、设备、触发和恢复方式。采集优先于制作示例。页面展示“原站观察”“视觉复现”“行为复现”的差异；截图证明观察，截图本身不能算交互复现。

值得展示且有证据的状态可用局部 HTML/CSS 复现；需要比较时提供并排快照或本地交互。无法独立复现的复杂组件用本地截图/片段展示并标明未完成行为复现。状态未知时展示待补测位置，不从别的网站借样式、不用浏览器默认焦点环冒充原站焦点规范。未知动效时长不补动画。

## 生成器输入

向生成器提供数据前由 Agent 按上述价值筛选；生成器不会自行判断元素是否有设计特色。运行 `python3 <skill>/scripts/build-page.py <output>/page-data.json --out <output>/index.html`。脚本将数据嵌入模板，无外部依赖；保留 JSON 供后续修订。模板提供起点，不限制复杂组件的表达。

可选 `documentTheme`：`{"accent":"#336DF4","basis":"measured","evidenceIds":["原站色彩证据"]}`。生成器据此派生浅底与可读强调色，六位 HEX 且必须有原站证据；不传时保留默认主题。

数据顶层：`title`, `sourceUrl`, `summary`, `date`, `coverage`(文字数组), `colors`, `typography`, `layout`, `components`, `motion`, `pages`, `gaps`(文字数组), `attachments`。集合可为空，页面会显示覆盖缺口。

`foundations` 可按 `style`、`spacing`、`padding`、`radius`、`border`、`shadow`、`icons` 提供条目数组（含 name、value、note 及通用证据字段）。`padding` 合并展示在「间距」下，使用 `sides: {"top":"0px","right":"16px","bottom":"0px","left":"16px"}`，未知为 null，示意图只在四边数据齐全时绘制。边框条目的 `styles` 提供已确认的 `border-width`、`border-style`、`border-color` 及可选尺寸和圆角，参数与小样例侧排。阴影条目可用 `shadowLayers` 数组提供 color、opacity、offsetX、offsetY、blur、spread、inset（值使用带单位的字符串；inset 为 true/false），未测量为 null 或省略；样例的 `styles.box-shadow` 仅填已确认的原始值。布局单独使用 `layout`。只有实际观察到左侧导航加内容网格的结构时，才可设置 `layoutDiagram: "sidebar-grid"` 输出示意图；示意图不代表精确尺寸。

颜色可加 `group`（如品牌色、主色、辅助色）与 `usage`（实际用途）；输入 HEX 可含透明通道，页面统一显示六位大写色值及独立不透明度。可选 `fontFamilies` 以 `english`、`chinese` 字符串数组列出声明的候选字体，`note` 说明实际渲染是否验证；字号使用已测 CSS px，模板据此从大到小排列，并以中文标签显示文字参数。通用模板与定制页都使用连续阅读目录，空分类隐藏；模板只负责呈现已提供的数据，不自动推导未知参数。

通用条目包含 `name`, `note`, `basis`（measured/observed/declared/inferred/untested）, `evidenceIds`。颜色加 `value`；字体加 `sample` 和 `styles`；布局加 `value`。组件加 `category`（可使用 navigation/buttons/cards/tags/inputs/forms/overlays 或对应中文名称；网站特色分类使用自然语言名称），可选 `categoryDescriptions` 为分类提供简述。可选 `presentation` 为 compact/panel/overlay，`presentationNote` 说明文档辅助背景或布局。组件加 `kind`（button/input/textarea/div）、`label`、`states`。每个状态包括 `name`（状态英文名）、通用证据字段、`styles`、可选 `label`/`screenshot`、`rendering`（reconstruction 或 screenshot）。`screenshot` 可填状态裁图；kind=div 可以展示简单表面，复杂 DOM 需扩展模板，不能称已还原。

样式使用 CSS property→字符串字典。生成器拒绝未知样式属性与 URL/表达式；不支持任意 HTML/JS。基于截图近似的复现注明不确定参数，basis 仍是原站证据等级，rendering 单独说明呈现方式。untested 状态不接受 styles 或 screenshot。

动效条目可含 `frames`（仅 opacity/transform/filter）、`duration`（毫秒）、`easing`。仅 measured 且证据编号非空、时间与关键帧齐备时启用重播；观察描述保留但不播放推测动画。减少动效偏好下不自动播放，用户明确操作才可重播。

附件包含 `label`、`href`，仅相对路径或 http(s)；拒绝 javascript/data 等协议和绝对本地路径。证据 JSON / 原始样式附件随目录保留，由工程文件访问，不在读者页面提供下载入口。导出前清除表单值、账号信息与敏感 URL。

## 验收

在隔离预览中检查宽屏和窄屏：导航与组件不溢出，样张不修改文档壳层，所有控件可用键盘，状态切换实际改变对应样例；未知状态有明显标记。检查截图和附件能打开，预览无页面错误，不联系原站接口、不产生登录/收藏/提交副作用。最后一轮允许带缺口交付，但须列明缺少的状态与复现程度。

## 文档大纲与组件详情

保留 CatchWeb-Design 壳层，以四个一级类组织左侧目录：

1. **概览**：整体概括、设计风格与可确认的网站特色。
2. **基础**：色彩、字体、间距、布局、圆角、边框、阴影、图标。目录暂按此组织，具体展示细节继续沿用已有规则，后续按用户确认迭代。
3. **页面**：采用上述常见分类与按设计价值筛选的网站特色分类，分类本身作为二级菜单；分类里的变体和样例在正文展示，不再平铺为二级菜单。
4. **交互动效**：按实际观察记录滚动效果、组件反馈、加载及过渡等特色行为；未观察的动效不补造。

组件状态的静态外观放在「页面」对应元素中；变化过程、触发、时长等放在「交互动效」，可互相链接并复用同一证据。采集说明保存在工程附件，不加入页面导航。右侧提供当前页的小节目录，窄屏改为可展开目录。目录搜索只筛选目录名称，不声称检索全文。

基础内容继续沿用既有展示规则：色彩按用途展示色卡；字体按展示标题、标题、正文、界面文字、辅助文字、注释等实际用途呈现参数；间距区分页面、容器、元素、列表和文字；布局展示容器、栅格、对齐和响应式结构，以图示说明。圆角、边框、阴影各自独立，阴影展示一个代表性效果及可复现的各项参数。图标仅在具有特色或多种值得比较的样式时展示，并说明风格、尺寸和摆放。不存在或无法确认的值不编造。把用户口语转换成准确专业名称，必要时配简短易懂的解释。

组件详情沿用前述展示规则：简述与用途 → 视觉样例与已确认状态 → 必要尺寸与内部布局 → 影响解读的限制。原始 CSS、本地复现代码、Token 绑定和证据索引保存在工程附件，用户要求工程详情时再提供；不将本地样例冒充原站组件库 API。

组件数据的 `category` 与生成器输入约定一致。旧格式 general/navigation/entry/display/feedback/other 可按本地 kind 和别名兼容归类，不把文档分类认作原站组件库的官方分类。`usage` 表示研究归纳的使用场景，`tokens` 仍可保存于工程数据。

图标仅在图标风格具有辨识度或样式之间存在值得借鉴的差异时展示；未入选时不显示空的图标菜单。用户明确要求分析图标时例外。
